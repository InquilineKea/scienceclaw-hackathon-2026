# Isolated local CPU diagnostic: static review and approval boundary

The previous NGC x86/CUDA image is not installed or executed on this Mac. Its review identified an old dirty vendor build and historical HTTP-keyring build step. The proposed CPU diagnostic instead uses native ARM64 Debian GROMACS2022.5-2. This is a different runtime from the failed2023.2-dev CUDA binary and cannot by itself identify a GPU-specific bug.

Inspected: the existing Debian12 image pinned tosha256:321341744acb788e251ebd374aecc1a42d60ce65da7bd4ee9207ff6be6686a62 (static image export, configuration and history; no container started), official Debian bookworm ARM64 package index and InRelease, seventeen selected binary/data packages, their control files and maintainer scripts, static ELF dependencies, and the staged runtime manifest/Dockerfile. All package sizes and SHA256 values match the index. The compressed package index matches the InRelease SHA256. Two InRelease signatures validate with the public Debian archive keyring from the pinned base; a third signature uses a key absent from that older keyring. The overall gpgv exit status is therefore2, not an all-signatures-success result. This is explicitly not hidden. Base-image publisher signing/reproducible-build attestation and a current comprehensive CVE/SBOM assessment were not verified.

Findings and mitigations:

- MEDIUM supply-chain/runtime uncertainty: official packaged native binaries and libraries remain third-party native code, and GROMACS2022.5 and the base/package set are old. Signed metadata/hash identity is not proof of source/build integrity or absence of vulnerabilities. A fresh independently reviewed source build would be a separate, more expensive diagnostic runtime.
- MEDIUM host isolation residual: Docker Desktop shares a virtualization/daemon attack surface with the host. No container sandbox is an absolute boundary. The diagnostic will have no network, GPU, capabilities, host home, credential, SSH-agent, Docker-socket, personal-file or browser-profile mount; non-root1000, no-new-privileges, read-only root/input, bounded CPU/memory/PIDs and a dedicated output folder only.
- LOW package lifecycle risk: inspected BLAS/LAPACK pre/post/removal scripts manage alternatives; other library triggers request ldconfig. None will be executed. Runtime staging copies only reviewed executable/library/data bytes. No apt/dpkg, installer, package hook, shell pipeline, remote script or publisher launcher runs in the proposed Dockerfile, which has no RUN instructions. MPI executables/libraries are omitted. No X11 socket or GUI access is provided despite the serial binary's X11 library linkage.
- LOW data-path risk: numeric input topology dependencies were reviewed in the original study and remain fixed. Only the selected scientific input folder is mounted read-only; all tool working/output paths are in a new writable diagnostic folder. The preceding read-only-working-directory bug will not recur. Warning suppression is forbidden.
- Prompt-injection review: package metadata, model files and publisher scripts are untrusted data. No repository instructions or author launch scripts are executed. Original local preparation/analysis scripts use Python standard library only.

Proposed execution: build the prepared image from the pinned existing base and staged files (COPY-only; no downloaded code or build command), query version, strict grompp from reviewed inputs, then bounded CPU-only tests with 4CPU/8GiB, no GPU/network. First benchmark1000steps to estimate cost. Total dynamics wall budget30minutes; no attempt to fill this budget if a meaningful failure occurs first. Compare original5.5fs and conservative2fs settings where time permits, one factor at a time; retain logs, checkpoints and diagnostic PDBs. A shorter-than-failure-window pass will be labeled incomplete, not a fix. No H100 restart or cloud spending.

No local imported molecular binary, container entrypoint, package script or simulation has run. Local execution is pending the user's explicit approval after this review, as required by their AGENTS.md. A clean static inspection does not establish safety.
