# Large-data publication review — 2026-10-31

Scope: original standard-library Python changes to upload-run.py, large_data.py, restore-large-data.py and their offline tests. Existing Git and GitHub CLI are reused; no package, third-party source, installer, container, workflow action or dependency is added or executed. No GPU job is run.

- Medium: the authorized destination is public. Exact sealed inventories, credential-pattern/path rejection and no symlink export reduce accidental disclosure; pattern scans cannot prove arbitrary binary content contains no private information. The integration archive uses already-public frozen scientific folders only.
- Medium: host-side authenticated publication can change GitHub. Destination is fixed to InquilineKea/scienceclaw-hackathon-2026; Git hooks and global Git configuration are disabled; only the existing CLI credential helper is used. Scientific subprocesses do not receive that session. No token values are read, printed, stored in source or sent to data downloads.
- Medium: interruption/concurrency can leave drafts or a committed index before all public links work. Success receipts require published releases. Exact hashes support retry without recomputation; existing different files/assets/tags are rejected. No force-push, clobber, asset deletion or tag replacement is implemented.
- Low: large archives need temporary disk space of up to one 1 GiB part during upload, and the complete file during restoration. Bytes are streamed; temporary parts are removed only from the uploader-owned temporary directory. Source data is never deleted.
- Low: recovery downloads untrusted bytes, verifies each part and original SHA-256, rejects path traversal and symlinks, and writes using an exclusive final link. It does not execute or extract archives. Only the expected public GitHub repository asset URLs are accepted.

Inspected all new source paths, subprocess calls, filesystem operations, URL construction, release mutations and test doubles. Offline tests exercise corruption, collisions, multi-part reconstruction, release sharding, interruption after the Git commit, starter-asset retry, secret signatures crossing read boundaries and exact inventory coverage. Live verification additionally downloads the actual published archive and checks its bytes. Existing CLI binary/package provenance was not re-established; a passing test or scan is not proof of absence of all vulnerabilities. Repository-administrator deletion cannot be prevented by this client.
